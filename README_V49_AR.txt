LibraryPrintApp v49 — التحديث الاحترافي للإدارة التجارية وسهولة التشغيل
====================================================================

هذه نسخة تطويرية من مشروع v48.4 المرفوع. تم الإبقاء على قاعدة البيانات المعتادة وشاشات الطباعة والوظائف السابقة، وإضافة دورة مبيعات ومخزون ومشتريات أكثر ترابطًا.

تصحيح الواجهة العربية (RTL)
-----------------------------
- تم توحيد ترتيب أشرطة الأدوات والحقول لتظهر عناصر الإدخال والأزرار من اليمين إلى اليسار.
- تم عكس ترتيب الأعمدة المرئي في الجداول العربية مع الإبقاء على آلية الرسم الآمنة في WinForms.
- تم إصلاح تمدد جداول الإدارة التجارية لتملأ عرض الصفحة بدل التوقف عند مجموع العروض الثابتة للأعمدة.
- تم تحسين ارتفاع صفوف وعناوين الجداول، وضبط نسب أعمدة سلة البيع وعرض أزرارها السفلية.
- تم ضبط شريط تبويبات الإدارة التجارية ليبدأ من اليمين.
- التفاصيل وقائمة اختبار الواجهة موجودة في UI_LAYOUT_FIXES_AR.txt.

قبل أول تشغيل
-------------
1) احتفظ بنسخة احتياطية من قاعدة البيانات ومجلد بيانات البرنامج كاملًا.
2) فك ضغط المشروع في مجلد جديد؛ لا تستبدل مجلد النسخة العاملة.
3) لا تنسخ قاعدة بيانات تجريبية فوق قاعدة بياناتك الفعلية.
4) شغّل أول نسخة بعد أخذ النسخة الاحتياطية، وراجع قائمة الاختبار في TEST_PLAN_V49_AR.txt.

التشغيل والبناء على Windows
---------------------------
- يلزم .NET SDK يدعم net8.0-windows (ويُفضّل .NET 8 SDK أو أحدث) مع اتصال NuGet لاستعادة الحزم.
- افتح PowerShell داخل مجلد المشروع، ثم نفّذ `dotnet restore` وبعدها شغّل publish_win_x64.bat؛ أو نفّذ أمر النشر التالي مباشرة: `dotnet publish .\LibraryPrintApp.csproj -c Release -r win-x64 --self-contained true -p:UseAppHost=true -p:PublishSingleFile=false -o .\publish\win-x64`.
- عند نجاح النشر سيظهر المجلد publish\win-x64.
- انقل المجلد كاملًا إلى الجهاز المستهدف؛ لا تنقل ملف exe منفردًا.
- هذا التسليم يحتوي على ملفات المصدر والتحديثات، وليس ملف exe منشورًا؛ لم تتوفر بيئة .NET SDK/Windows Forms في بيئة إعداد الحزمة لتنفيذ نشر نهائي أو اختبار طباعة فعلي.

أهم ما تمت إضافته في v49
------------------------
1) سلة مبيعات متعددة الأصناف:
   - بحث بالاسم أو الباركود، وإضافة سريعة للأصناف الأكثر مبيعًا.
   - دمج السطور المتطابقة، وتعديل الكمية والسعر والخصم، وحذف السطر.
   - دفعة جزئية، وحساب الدين والباقي، وربط العميل عند وجود دين.
   - تنفيذ كل سطور البيع وتحديث المخزون والخزينة وسجل المراجعة داخل معاملة SQLite واحدة.
   - تعليق السلة واسترجاعها، مع فحص المخزون الحالي. المسودة لا تخصم مخزونًا ولا تسجل حركة مالية.
   - المسودة المسترجعة لا تُحذف إلا بعد نجاح البيع، أو تُستبدل ذريًا عند إعادة تعليقها.

2) الموردون والمشتريات:
   - إضافة الموردين وحفظ بيانات التواصل.
   - تسجيل فاتورة شراء متعددة الأصناف مع المدفوع والمتبقي.
   - تحديث الكمية ومتوسط تكلفة الشراء المرجح.
   - سداد المورد وتوزيع الدفعة على أقدم الفواتير المفتوحة.

3) رقابة المخزون:
   - سجل حركة دخول وخروج للصنف (شراء، بيع، مرتجع، تعديل يدوي، واستيراد CSV).
   - ربط الحركات بالمستخدم والمرجع وسجل المراجعة.
   - استيراد وتصدير CSV مع فحص الأعمدة والكميات والأسعار قبل الحفظ.

4) مرتجعات مبيعات المخزون:
   - مرتجع جزئي أو كامل مرتبط بعملية البيع الأصلية.
   - إعادة الكمية للمخزن ورد المبلغ من حساب المبيعات.
   - تسجيل سبب المرتجع والمستخدم والحركة المالية والمخزنية.
   - حساب فرق التقريب في آخر مرتجع حتى لا يتبقى جزء من المبلغ بسبب التقسيم.

5) الأرباح والتقارير:
   - حفظ تكلفة شراء الصنف وقت البيع حتى تظل ربحية العملية القديمة ثابتة بعد تحديث تكلفة الصنف.
   - تقرير الفترة بهامش الربح المعروف، تكلفة البضاعة، المرتجعات، العمولات، وبعض المصروفات التشغيلية المسجلة.
   - تفصيل حسب الصنف والموظف.
   - المبيعات القديمة بلا تكلفة تاريخية والمرتجعات التابعة لها تظهر منفصلة؛ لا يتم اختراع تكلفة أو ربح غير معروف.
   - إيرادات الطباعة تظهر منفصلة لأن تكلفة الورق والحبر والصيانة ليست مسجلة لكل عملية.

6) الفواتير والبحث:
   - أرشيف فواتير للبحث برقم الفاتورة أو اسم العميل، مع فتح الفاتورة وإعادة معاينتها/طباعتها.
   - حفظ لقطة ثابتة للفواتير الجديدة حتى لا تتغير تفاصيلها عند تعديل الأصناف لاحقًا.
   - بحث موحد عن الأصناف والعملاء والموردين وعمليات البيع والفواتير.

7) الطباعة وسهولة الاستخدام:
   - حفظ قوالب مسماة لإعدادات الطباعة وتحميلها أو حذفها.
   - لا يتم حفظ نطاق صفحات ملف معين داخل القالب أو الإعداد العام.
   - زر الإدارة التجارية من لوحة التحكم، واختصار Ctrl+M.
   - زر واتساب يفتح رسالة تذكير بالرصيد مجهزة؛ يقبل أرقامًا محلية مصرية أو رقمًا دوليًا مكتوبًا بعلامة + أو 00، ولا يرسل تلقائيًا.

قاعدة البيانات والتوافق
-----------------------
- قاعدة البيانات لا تزال في المسار المعتاد:
  %LOCALAPPDATA%\LibraryPrintApp\library.db
- التهيئة تضيف الجداول والأعمدة الجديدة إلى القاعدة الحالية دون حذف الجداول القديمة.
- تم استخدام ترحيلات CREATE TABLE IF NOT EXISTS وALTER TABLE عند غياب الأعمدة.
- رغم ذلك، يجب أخذ نسخة احتياطية قبل أول تشغيل؛ لا يوجد ضمان بديل عن النسخة الاحتياطية عند التعامل مع بيانات عمل حقيقية.

حدود النسخة الحالية
-------------------
- لم تُضف بعد صلاحيات دقيقة مستقلة لكل زر وعملية؛ صلاحيات الدخول الحالية كما هي.
- لم تُضف شاشة طباعة ملصقات باركود.
- لا يوجد احتساب لتكلفة الورق والحبر والصيانة لكل طابعة، ولا تقرير ربحية مستقل لكل طابعة.
- مرتجعات الشاشة تخص أصناف المخزون؛ دورة مرتجعات خدمات الطباعة/التصوير أو الاستبدال بين صنفين ليست مكتملة.
- إذا كان على العميل دين مرتبط بعملية قديمة، فقد يمنع المرتجع حتى تسوية رصيد الحساب؛ لأن دفتر الديون القديم لا يربط جميع الدفعات بفاتورة بعينها بصورة كافية.
- الفواتير الجديدة تحفظ لقطة ثابتة. بعض الفواتير القديمة قد تُعاد بناؤها من السجلات المرتبطة بها ولا تضمن مطابقة محتواها تمامًا إذا كانت عملياتها الأصلية قد حُذفت أو تغيرت.
- صافي الربح المعروف تقديري للجزء الذي تتوفر له تكلفة تاريخية، ولا يشمل أي مصروف غير مسجل أو تكلفة مستهلكات الطباعة.

حالة التحقق
------------
- تم فحص توازن الأقواس والاقتباسات في الملفات المعدلة بفحص ساكن.
- تم تنفيذ مخططات قاعدة البيانات والترحيلات الجديدة على SQLite تجريبية مع تفعيل المفاتيح الخارجية.
- تم فحص 14 استعلامًا أساسيًا من المصدر بنجاح، واجتازت قاعدة الاختبار `integrity_check` ولم تسجل مخالفات في `foreign_key_check`.
- لم تتوفر أداة dotnet أو مترجم C# في بيئة إعداد الحزمة، لذلك لم يمكن تنفيذ dotnet build أو تشغيل WinForms أو اختبار الطابعات فعليًا هنا.
- يجب تنفيذ Build وتشغيل تجريبي على Windows قبل استخدام النسخة في الشغل اليومي. قائمة الاختبار في TEST_PLAN_V49_AR.txt.
